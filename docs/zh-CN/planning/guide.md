# 学期规划

[English](../../planning/guide.md) · 简体中文

打开**我的空间 → 学期规划**（`/planning`），选择 Student Plan、Standard Audit、Expanded Audit (Beta) 或 Compact Audit，并指定 BDP 导出或浏览器打印。推荐先导入 Student Plan，再单独核对 Planned Standard；Expanded 可补充约束背景。默认导入会将独立来源快照追加到同一工作区，相同课号不会静默覆盖其他记录。只有明确选择“替换”才丢弃草稿；需要保留时请先导出。

## 本地流程

1. 选择不超过 20 MB、100 页的文本 PDF。暂不支持加密或扫描文件。由随应用打包的 PDF.js worker 在本地提取，不向外部 PDF 服务发送文件。
2. 对照原文件逐项检查候选。可修改学科、课号、学分、类型和来源状态，删除错误行，补充课程及学期。空白学分表示未知。学期格式为 `Autumn2026`、`Spring2027` 或 `Summer2027`。
3. 将 Applied Version（如 `AU2017`）与 Catalog Term 分开。Applied Version 来自 SIS plan/sub-plan 要求学期，不是 PDF 发布日期或入学年份。不同要求可能使用不同版本，冲突版本保持未知。
4. 确认审核后，在当前浏览器保存或导出结构化 JSON。修改字段会取消审核状态。当前浏览器保存一个包含多份来源快照的工作区；载入或明确替换非空草稿前会确认。删除本地规划会移除工作区并清空草稿，导出文件需自行删除。编辑、载入、删除或取消会使正在执行的导入失效，防止较晚完成的解析覆盖新状态。

课程链接复用已有课程搜索、详情与评价入口。打开课程会通过现有搜索流程发送所选课程查询，不包含 PDF 或其他规划内容。

## 解释边界

这是候选提取和规划编辑器，不是毕业审核、先修约束求解器、注册系统或课表冲突检查器。尚未验证所有 BDP 输出。版式研究仅覆盖一名学生的导出族；仓库不含私人附件及其原文。自动化测试使用合成数据。

Standard 和 Expanded 审核可能在多个要求节点重复列出课程。候选仅在同一提取分组中去重，不计算累计审核学分，也不合并剩余学分。审核文件的课程学期保持未分配。Compact 双栏版仅有限支持；浏览器打印顺序也不受信任，保持未分配。转学分和考试学分未经核对不能当作普通上课学期。未知格式可能无法提取候选，此时需手动输入。Expanded 中明确的学分/课程数量下限及 all/any 标记可提取为要求候选；由缩进推测的层级、规则及课程分配都需明确核对。未知条款、例外、GPA 规则和先修逻辑不求解，不保存原文和成绩。Standard、Compact 的要求树仍需手动重建。

有课号也可能是占位项。PDF 的 “Planned” 不证明尚未注册。学期总学分 13 不能确定标为 `-` 的占位项学分，未知仍为空。课程候选和来源总学分分别保存。请与顾问确认学位要求及注册情况。

## 隐私边界

原始文件、文件名、姓名、学号、联系方式、顾问信息、成绩、自由备注及提取原文不保存、不导出。处理完成后释放提取内存并销毁 worker。第 2 版私有模型仅允许枚举来源、本地引用 ID、项目代码、各项目独立版本、学期、课号、学分来源、数值规则候选、分配、页码和审核状态；保存时剔除未知字段。第 1 版快照读取时自动升级。项目与要求字段只能填写学术代码，不得填写个人姓名。浏览器存储可能失败或被清除，请按需导出备份。本地存储未加密，能访问浏览器配置或运行同源脚本的人仍可读取。

删除姓名后，课程组合仍可能识别个人。JSON 是私人信息，不是匿名公共数据集。当前没有贡献或公开分享接口。将来的公共样本库必须采用独立、明确选择加入的流程与服务端白名单，不能把私有快照直接转成公开种子。

规划页面禁止第一方事件及分析载荷，规划内容屏蔽会话回放，导航入口执行整页跳转以销毁已加载的录制器。原始 PDF、提取全文和身份信息不发送到诊断。网站现有账号会话和资源请求仍可能独立发生；“PDF 本地处理”不意味着整个网站没有网络请求。

## 官方培养方案目录

当前仓库包含 12 个来源入口、1 份待人工复核的分子遗传学结构化样例，人工审核通过的结构化方案为 0。并未覆盖全校专业。按学院分类的专业索引仅是发现基准，不是培养方案 API。项目、部门和分页搜索结果不能视作同一个全集。历史版本可能不完整或仅顾问可见。

来源记录、培养方案版本与私有规划分离。每个版本保留来源 URL、SHA-256、抓取和验证日期、文档类型、专业、方向、校区、GEN/GEL、适用范围、证据、学分区间和审核状态。未知适用范围保留 null。样例规划不能提升为正式要求。适配器支持分子遗传学页面，以及具有八个明确学期 caption 和 Course/Credits 列的严格公开 HTML 表格。未知备选项或表格格式保持待审，不会扁平化猜测。分子遗传学预览保留公开来源中的课程备选证据，使用前仍需核对原始脚注。官方 PDF 暂不支持自动结构化。发布状态（含草案）、单/多专业范围、学年分别独立于来源版本、Applied Version 和 Catalog Term。草案不能批准为权威正式要求。目录另含双专业样例、作曲草案、数学替代课程参考和开课可能变化的地质样例，均不代表通用要求。

## 运维与架构

浏览器使用 `src/lib/planning/model.ts`、`parser.ts`，通过 `pdf.ts` 按需加载 PDF.js。私有存储键为 `course-atlas:private-planning:v1`，独立于收藏、账号同步和公开交换。没有私有规划后端。`snapshots.ts` 在追加来源时重映射引用，保留各项目剩余学分但不累加；删除来源会清理其要求及分配。`SourceReview` 提供项目版本、嵌套 all/any/最低数值规则、学分来源纠错与分配确认。同一课号在每项已核对规则中只计算一次，冲突学分记录保持未解决。顶层版本字段仅作兼容摘要，详细出处以文档和项目记录为准。

公共培养方案在生产使用 `osu_planning`，开发使用 `osu_planning_dev`。`PLANNING_SCHEMA` 允许以 `osu_planning_` 开头的隔离名称。`source_document` 保存不可变来源标识；`curriculum_version` 保存明确的样例/要求版本和审核信息。SQL 均通过专用命名空间解析。该独立域自行初始化、备份并永久保留版本，账号备份不包含它。

在仓库根目录运行：

```sh
# 仅公开网络请求，不使用凭据；仅写本地缓存。
python3 scripts/planning/sync.py --delay 2 --limit 8
# 恢复发现；--refresh 才重新访问已下载来源。
python3 scripts/planning/sync.py --delay 2 --limit 20
# 仅本地转换，所有候选保持待审。
python3 scripts/planning/structure.py
# 输出操作计划，不连接 PostgreSQL。
node scripts/planning/database.mjs init
node scripts/planning/database.mjs retention
# 配置隔离的 PLANNING_DATABASE_URL 后，显式执行：
node scripts/planning/database.mjs init --apply
node scripts/planning/database.mjs import <candidate.json> --apply
node scripts/planning/database.mjs backup <new-backup.dump> --apply
```

先使用可丢弃的 PostgreSQL 数据库和测试凭据。规划数据库命令仅需 `PLANNING_DATABASE_URL`；本地编辑、解析测试、lint、typecheck 和 build 不需要生产凭据。既有可选服务仍参考 `.env.example`。禁止用学生 cookie、HAR 凭据、partner API token 或登录会话发现来源。不得提交私人附件、HAR 或学生提取原文。

抓取器仅允许公开 HTTPS `osu.edu` 域，拒绝凭据、查询字符串及自动重定向，检查 robots，请求间隔至少 1 秒（默认 2 秒），下载上限 8 MB，并原子保存恢复点。请求失败、robots 不允许和未知格式保持待审。刷新时缓存保留先前版本，不自动发布或猜造要求。分别检查 `state.json` 的发现、下载、待审计数及生成候选。审核后可由 cron 调用幂等工具；本功能没有安装生产定时任务。

审核前需核对原文、脚注、适用范围和替代规则。批准必须包含审核人、审核日期及来源验证日期。入库使用事务和不可变插入，重复 ID 无操作；修正或更改审核决定需同时使用新 ID 和新版本。备份由显式 `pg_dump` 自定义归档产生，应在可丢弃数据库验证恢复。所有来源和版本永久保留，没有自动删除命令或生产清理任务。

## 验证

各脚本见[测试说明](../testing.md)。浏览器场景在内存中生成合成 PDF，检查导入、纠错、审核门槛、保存/导出、来源目录、中英语言，以及 320/390/768/1440 像素浅深色布局，并检查 POST 正文是否泄露合成私人内容。真实 PostgreSQL 和完整浏览器验证需要可访问的隔离服务器及支持浏览器的环境。受阻不等于通过。

## 离线 HAR 对照与 OCR 决策

明确选择的私人回归工具可在设置 `PLANNING_PRIVATE_PDF_DIR` 时同时设置 `PLANNING_PRIVATE_HAR_COMPARE=1`。工具仅读取响应正文，处理 JSON anti-XSSI 前缀和 base64 编码，只输出汇总计数，不发送请求、不持久化提取记录。附件和 HAR 必须放在 Git 与公共 CI 之外。这是开发者回归工具，不是浏览器 HAR 上传功能。

提供的归档包含 74 个可读 JSON 响应。符合个人计划结构的响应包含 2 个学期分组、7 条课程记录和 4 个占位项。7 条唯一匹配的课程与 Student Plan 候选的学分、日历年份全部一致，两个课程分组内部一致，占位项数量一致。1 条明确计划状态一致。对照结构中的 7 条注册状态均未知，不能据此判断是否已注册。这些是一个学生的重叠快照一致性计数，不代表一般解析准确率、召回率或完整审核验证。发现 9 个需求树和 9 个审核快照，但未建立可靠的 PDF 需求节点语义映射，需求准确率和召回率仍未测量。Expanded 的 78 个需求候选和 162 个分配候选仍须人工复核。

11 份私人 PDF 的 71 页均有文字层，因此继续优先使用文字坐标；已发现的故障来自排版和符号解释。本次不增加 OCR 依赖或后备，纯图片扫描仍不支持。浏览器 worker 加 WebAssembly 在技术上可实现 OCR，但 [Tesseract.js 不直接支持 PDF](https://github.com/naptha/tesseract.js/blob/master/README.md)，需先本地栅格化页面。未来可选后备须固定并本地提供 worker、WASM 与语言资源，文档处理时不访问远程推理或 CDN，限制分辨率、页数和内存，支持取消并强制预览。OCR 可能误识别课号、后缀与小数学分，也不能解决双栏顺序或需求语义。手机内存与耗时、扫描件准确率和离线资源加载尚未实测；现有文字层样本不能证明 OCR 会改善结果。
