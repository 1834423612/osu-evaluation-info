# 大纲历史版本与比对

[English](../../syllabus/history.md) · 简体中文

**大纲的“来源版本更新”，不一定等于老师改了正文。** 学校可能更新修改时间、网页结构或表格格式，而文字一个字没改。旧界面只统计文字行数，因此会出现“有新版本，但增加 0、删除 0”。问题主要在于界面没有解释这两种“更新”的区别。

## 现在怎么看

历史比对可切换 **文档比对** 与 **逐行比对**。文档比对保留标题、列表、表格，用绿色标新增，用红色和删除线标删除。两个模式都使用经过安全清理的归档内容。能比较归档中的链接目标、图片地址与替代文字，但不会抓取并保存同一 URL 下 PDF/图片的文件字节版本；归档文字相同，不能据此证明远端附件文件也没变。文字没变时，会明确说明是格式、链接、图片、来源记录或归档表达发生变化，不再让用户猜是不是比对失效。

同一来源、同一修改时间、相同组件信息与标准化渲染内容的重复归档，会在历史列表中合并展示。官方修改时间确实推进的记录仍保留，即使正文没变。原始数据库归档不会删除，历史条数上限也在合并重复项后计算。

Simple Syllabus 会产生类似 `editor-0.12345` 的临时编辑器 ID。现在渲染和计算内容摘要前会去掉这种临时 ID，避免仅因随机 ID 不同就产生新内容版本；稳定的页面锚点仍保留。已有归档和历史摘要不会被重写。

## 2026 年 11 月 26 日实际查到了什么

这次只读检查了 **16,954 条历史版本、8,332 个大纲文档 ID**。其中 7,062 个文档有多个版本，形成 8,622 组相邻的不同摘要版本。

| 实际差异 | 数量 | 直白解释 |
| --- | ---: | --- |
| 正文文字变化 | 47 组 | 确实改了文字，增加和删除行数有意义。 |
| 原始网页标记变化，文字没变 | 6,921 组 | 例如加了样式 class，或把普通表格单元格改成表头；文字行数还是零。 |
| 来源信息和临时编辑器 ID 变化 | 1,637 组 | 来源记录更新了，但标准化后的可读内容相同。 |
| 旧归档后来补充了原始渲染内容 | 17 组 | 本地归档表达更完整，不能据此断定老师改过正文。 |

后三类合计 **8,575 组没有文字差异**。旧逻辑首次分类时，把其中 8,574 组算作原始渲染差异，另 1 组算作安全清理后的 HTML 差异。后者是 `PHR 3440`：表格增加了表头语义，文字不变。`CHEM 1110` 则有官方修改时间推进、标准化可读内容相同的实例。这是此次存档的检查结果，不代表今后所有学校更新都如此。

所以，很多“零增加、零删除”确实没有正文修改，并不是程序凭空漏掉几段文字；但旧界面的说法容易误导。修复后会清楚告诉用户“到底变了什么”，也不会把每次格式调整都说成老师修改了课程内容。
