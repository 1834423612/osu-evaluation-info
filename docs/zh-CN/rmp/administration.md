# RMP 数据核对后台

[English](../../rmp/administration.md) · 简体中文

`/admin/rmp` 用于管理课程标签关联。列表展示原始 RMP 课号、教授档案、校区、当前关联、原因、官方授课证据、候选和评论样例。课程代码/官方课程名、教授/档案 ID、评论或证据关键词、状态、校区可以组合筛选，并有分页。电脑使用紧凑表格，手机优先展示身份与状态，完整信息在详情面板中查看。

## 什么可以自动关联，什么需要人工确认

`1131` 只有编号，没有学科。新规则用**同校区已核验的教授身份 → 官方授课学科 → 官方精确课号**寻找候选。院系名称本身只能提供线索，不能直接把数字绑定成正式课程。多个学科有同号时，即使其中一个有明确授课记录，也保留歧义；数字课号推断不能反过来证明教授身份。

课程标签关联也不等于“已证实这位老师教过这门课”。推断来源会保留，身份未确认的档案仍作为待确认线索展示。原始评论、课号、教授 ID 和身份映射都不会被改写。

人工决定按**教授档案＋校区＋标准化原始标签**生效，会影响该组全部有效评论。确认前看清评论数量与样例；如果历史上同一个数字混用了不同课程，应该继续保留歧义。绑定、解绑、拒绝都是持久覆盖，解绑/拒绝也会屏蔽旧的精确课号兜底。后续同步和结构重建不会清掉人工决定；多人同时修改会报冲突，不会覆盖较新的决定。

批量操作与可编辑的理由模板便于快速处理明显案例，提交前统一预览每个目标和影响范围，再确认。AI 仅生成待审核建议，不会直接改正式绑定。见 [AI 辅助核对](assistance.md)和[界面参考](../design/reconciliation.md)。

## 安装与登录

管理功能正式上线前，先执行经过核对的生产结构迁移：

```bash
: "${REPORT_DIR:?Set REPORT_DIR to a private operator report directory}"
mkdir -p "$REPORT_DIR"
pnpm rmp:admin:migrate --production
pnpm account:migrate --production --output "$REPORT_DIR/account-migration.sql"
# 核对输出的账号迁移后：
pnpm account:migrate --production --apply
```

生产入口需要：已验证的现有账号、数据库中当前有效的管理员角色、30 分钟内建立的登录会话、现有维护密钥二次解锁。未解锁页面提供“账号”和“解锁管理员工具”入口。不使用邮箱白名单，也不会让第一个访问的人自动成为管理员。[管理员角色说明](../admin-roles.md)包含首个管理员授权、后续面板授权/撤销和审计。

本地开发：

```bash
pnpm rmp:admin:migrate
RMP_ADMIN_SCHEMA=osu_rmp_dev pnpm dev
```

开发启动器验证真实连接来源，并在内部代理转发时保留原始地址。只有开发模式加可证实的本机回环或 Tailscale `100.64.0.0/10` 才放宽访问；客户端自己填写的 Host、转发地址头不能证明权限。直接运行 `next dev` 不会安装这层验证。免鉴权状态有明显警示。

开发人工决定保存在 `osu_rmp_dev`。设置 `RMP_ADMIN_SCHEMA=osu_rmp_dev` 后，公开开发页面也能预览这些覆盖；不设置时，管理页仍隔离写开发决定，但公开开发页面读取生产来源视图，警示会说明区别。生产决定保存在 `osu_rmp`。

## 核对已有课程标签

先在自己的 Python 环境安装 `scripts/rmp/requirements.txt`。仅课程关联脚本默认只读：

```bash
pnpm rmp:reconcile --output "$REPORT_DIR/course-plan.json"
node scripts/rmp/compare_course_plan.mjs "$REPORT_DIR/course-plan.json"
```

核对全部状态变化，不要只看新增关联。执行需要提供该份计划的前后两个摘要：

```bash
pnpm rmp:reconcile --apply \
  --expected-plan-sha256 "$PLAN_SHA256" \
  --expected-before-sha256 "$BEFORE_SHA256" \
  --output "$REPORT_DIR/course-apply.json"
```

映射同步与人工写入共用互斥锁。脚本会在写入前保存完整计划及旧的自动/人工记录快照，自动关联统一事务提交，提交后另写回执。失败日志给出阶段和安全的 SQLSTATE、schema、表、约束信息；提交后回执写失败不会被误报为“数据库已回滚”。此命令不修改教师身份、原始来源和人工决定。

如果已提交后要恢复自动关联，应在相同互斥锁事务里用之前的记录恢复，不能删除或回退此后产生的人工决定。仍需完整备份 RMP 数据域；执行前快照不能替代正式备份。

## 保留、备份与页面生效

备份整个管理 schema，包括 `course_decision`、`course_decision_audit`、`admin_migration`、AI 辅助记录及相关函数。生产为 `osu_rmp`，开发为 `osu_rmp_dev`。人工决定与审计保留，禁止删除/清空，审计也禁止修改。恢复时要带函数、触发器、视图，不能只恢复自动匹配表。身份角色在独立身份域备份恢复。

后台详情即时读取当前状态；已有公开摘要缓存可能最多需要五分钟反映新绑定。之后继续采集时，覆盖标识与审计来源仍保留。

## 2026 年 11 月 26 日只读试算查到了什么

共检查 **37,020 组课程标签记录**，其中 3,187 组为数字标签。旧结果为 11,545 组已关联、533 组有歧义、24,942 组未解决。新规则试算：

| 变化 | 数量 | 直白解释 |
| --- | ---: | --- |
| 未解决 → 已关联 | 157 组 | 在同校区已核验授课学科里找到了唯一官方课程。 |
| 已关联 → 有歧义 | 18 组 | 多个学科都有这个编号，旧规则选得过早。 |
| 已关联 → 未解决 | 465 组 | 大多原来只凭院系名称推断；其中 13 组缺少所需的官方课程证据。 |
| 未解决 → 有歧义 | 11 组 | 现在找到了多个候选，但没有乱选一个。 |

试算总数为 11,219 组已关联、562 组有歧义、25,239 组未解决。**教师身份、原始数据、人工决定都不变。** 另一些差异只更新候选或原因，不改变已接受的课程代码。

保留旧精确/别名查询语义后，用同一套实际公开查询比较：新增 551 个“评论—课程—校区”关联对，撤回 1,114 个弱证据关联对；通过原有身份核验门槛的关联对从 64,765 变为 65,088。这不是新增评论数或教师人数。这里记录的是只读计划，不能理解为生产更新已经执行。

## 官方证据与建议过期

手动绑定与 AI 导出使用同一套课程及校区查验：既包含已发布目录，也保留官方授课评价中的历史课程，因此旧课号不会仅因当前目录没有而被误判无效。课程标题联想只读取每个学期的最新完整发布批次，精确目标校验仍检查历史已发布记录和同校区有效授课事实。结果会标明证据来源及学期。

记录指纹同时覆盖原始教授及评论、已确认身份、实时官方授课证据和当前人工版本。即使自动匹配器还没重新运行，只要官方授课事实改变，旧批量预览和 AI 建议也必须重新取得证据后才能确认。
