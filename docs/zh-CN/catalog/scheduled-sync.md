# 定时来源同步

[English](../../catalog/scheduled-sync.md) · 简体中文

三个任务均使用现有 Actions secret `DATABASE_URL`。运行前显式迁移课程、大纲和 RMP 数据库结构。计划时间采用 America/New_York；GitHub 可能延迟启动。

| 任务     | 计划                 | 每次来源处理预算                                       | 作业上限 |
| -------- | -------------------- | ------------------------------------------------------ | -------- |
| 课程目录 | 每四小时的第 17 分钟 | 课程分页可续跑；更新历史回填最多 120 秒、12 个学期批次 | 30 分钟  |
| 教学大纲 | 每日 03:43           | 最多 1,500 秒或 1,800 份文档检查，先达到者生效         | 30 分钟  |
| RMP      | 周六 03:30           | 最多 1,200 秒或 120 次来源请求；请求间隔至少 10 秒     | 30 分钟  |

这些是处理上限，不代表预期耗时或更新时效承诺。环境安装、数据库提交和关联也需要时间。请求数或运行时间耗尽属于正常保存断点后暂停；来源、协议和数据库错误仍明确报错。不要通过缩短来源请求间隔消耗预算。

## 课程目录

完整且通过校验的学期快照先发布，再维护更新历史。历史比较每条 SQL 处理 200 个课程身份，避免在一条语句中展开整个学期。单个学期的变化事件与完成标记在同一事务提交；中断不会留下部分事件或错误的完成标记。有限预算回填从最早未完成的学期继续。

课程工作流仍仅由计划触发。本地可执行有限预算的维护重试：

```sh
node scripts/catalog/backfill_changes.mjs --max-batches 1 --max-seconds 60
```

该命令写入待补齐的变化历史，不重新抓取或删除课程快照。官方删除、当前版本和旧学期归档规则见[保留与学期生命周期](lifecycle.md)。

### 排查失败的运行

打开该次运行的 **Summarize catalog maintenance** 输出。摘要分别列出配置、检出、运行时、依赖、课程目录、RMP 依据、变化历史、搜索索引及校历的结果，并提供完整步骤日志链接。展开每个阶段可查看最后 40 行记录，每行最多 1,000 字符。Node 报告器无法启动时，环境安装失败仍有备用摘要。摘要会脱敏数据库网址、凭据和令牌字段，并将日志内容与工作流命令、Markdown 隔离。

结构化课程同步错误保留失败阶段与错误代码，GitHub 错误注解直接显示原因。`CATALOG_COVERAGE_REGRESSION` 拒绝还提供学期、校区、学科的差异表，比较上次通过与候选数据的班次数量，同时显示受影响比较总数。这类拒绝有意保留红色失败状态：不完整官方数据不会发布，也不会伪装为更新成功。上次通过的课程目录及其已接受索引继续可用。依赖安装成功且运行未取消时，索引修复与校历更新仍独立执行，应分别查看其结果，不要根据课程同步失败推断其他步骤状态。

## 大纲刷新

迁移 5 新增 `osu_syllabus.document_checks`，与永久保存的索引观察及正文版本分离，记录上次有明确结论的网络检查和当时的完整索引元数据。复用缓存不会推进检查时间；临时失败不会计为成功检查。

计划任务先刷新官方索引，再优先处理未检查文档、较新学期及最久未检查的文档。索引未完成时从分页断点继续；索引完成后，下次运行重新扫描索引并复用共享文档检查记录，避免正文积压阻塞新课程发现。

计划刷新间隔为：当前学期可读文档 168 小时、已结束学期 720 小时、缺失或受限文档 72 小时。索引元数据改变时直接重新读取。学期结束前一周，可读文档缓存最多复用 24 小时；学期结束后，如果来源仍可用，会再次检查可读文档。只有日期的结束时间附加 36 小时缓冲。来源学期不可用时保留最后一份完整归档。

官方索引不提供正文修改时间。因此，没有索引变化的正文修改依靠轮转网络检查发现，无法保证后台立即发现。用户打开大纲时仍沿用官方直连／本站转发流程检查来源。

```sh
pnpm syllabus:migrate
pnpm syllabus:sync --max-runtime-seconds 240 --max-documents 5 --refresh-hours 168 --archive-refresh-hours 720 --missing-refresh-hours 72
```

本地不指定参数时不限制运行时间和文档数量；当前学期及缺失文档间隔均为 24 小时，已结束学期为 720 小时。某类刷新间隔设为 0 时强制网络检查。其他参数及文档状态见[大纲运维](../syllabus/operations.md)。

## RMP 采集

采集器从已保存的游标和待处理评价分页继续。来源签名改变的档案立即进入处理；其余档案完整刷新间隔为 30 天。页面写入通过数据库 pipeline 减少往返，在完整性校验和游标提交前完成刷新。页面写入失败不会推进游标或完成评价移除处理。

运行预算使用单调时钟，请求间隔、重试等待和 HTTP 超时均受剩余预算约束。冷却时间无法纳入剩余预算时暂停，不缩短来源要求的等待。正常预算用尽后，仍会对已保存数据运行关联步骤。

手动 Actions 默认仅请求两次，允许 1–120 次。可先使用小预算验证配置，再等待正常计划任务。来源身份与课程关联不会捏造已确认的教师关系，也不会丢弃待确认档案。

## 已验证结果

2026 年 11 月 15 日，两次请求的 RMP Actions 在约三分钟内完成采集与关联。一次有限预算大纲同步复用了当前索引全部 7,851 条检查记录，没有请求正文。200 门课程的比较约耗时一秒；临时数据库结构测试还验证了结果与原 SQL 一致，以及中断后的事务回滚。这些是当日观察，不是性能承诺。
