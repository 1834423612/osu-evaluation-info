# 课程搜索引擎

[English](../../catalog/search.md) · 简体中文

检索词汇来自完整已发布课程目录，不维护少数学科的手写简称表。字段加权 BM25 召回结合规范化、学科名／缩写、编辑距离、拆词合词、课程号相邻换位和说明片段；歧义保留为候选，不能把搜索相似度用于教师身份确认。

完整代码使用轻量 `/api/catalog/subjects` 词表，唯一且足够明确时，浏览器在包含词表解析的两秒预算内尝试一页官方查询。冷浏览器可能另需官方学期元数据。空、慢、失败或歧义回到本地容错索引；不对其他课程号逐个向官方扩散请求。官方部分页保留不完整标记，打开课程再补全详情。

筛选条件必须同时匹配同一个班次；分页游标固定查询、筛选和已发布版本。搜索建议保留原输入，不偷偷修改用于评分的课程身份。普通浏览与精确查询、实时空位有不同的数据路径。

服务端相同查询合并一次排名与页面补全，缓存最多 96 页、序列化数据 12 MiB、120 秒；最多 128 个不同待处理键。词表另限 8 项／512 KiB，浏览器保留最多 8 学期词表五分钟。超额返回 429 与 Retry-After，不自动转向官方放大负载。数据库读取使用现有连接池和只读事务。

全量只读评估按学科覆盖代码、标题、描述、简称和多种拼写扰动，输出召回率、排名和耗时；不是少量人工样本，也不是生产成功率保证。2026-11-13 本机 200 个相同热查询的 p95 为 416 ms；首次冷描述检索仍需约 8.6 秒。该结果不等于 200 个不同线上查询的性能承诺。

## 命令与格式示例

以下示例与英文版使用相同命令、字段和参数；运行前按上文核对环境与影响范围。

```sh
node --expose-gc --env-file=.env.local scripts/search/evaluate.mjs /tmp/search-spring.json
SEARCH_EVAL_TERM=1268 node --expose-gc --env-file=.env.local scripts/search/evaluate.mjs /tmp/search-autumn.json
SEARCH_EVAL_TERM=1264 node --expose-gc --env-file=.env.local scripts/search/evaluate.mjs /tmp/search-summer.json
```

```sh
node scripts/catalog/benchmark-search.mjs
```

默认哥伦布校区即使未写入 URL，也会计入筛选数并显示选中标签。取消校区标签会切换全部校区；清除筛选同时移除校区限制，重置筛选恢复默认哥伦布校区。搜索文本、学期、排序以及详情／分享参数不计入筛选数。

## 在同步时预构建索引

先明确执行新增迁移，再为当前已发布学期构建一次索引，然后部署读取端：

```sh
pnpm catalog:migrate
pnpm search:prepare
```

两个命令都需要运维环境中的 `DATABASE_URL`。迁移执行 DDL；预构建只读取公开课程快照，
并写入派生的 `osu_catalog.search_artifacts`，不向翻译服务发送文本。测试不要使用生产凭据。

定时课程同步会先为暂存版本的每个学期构建完整索引，再发布新版本。构建失败时，
旧发布版本继续可见。更新后的同步要求迁移 6；定时任务本身不执行 DDL。
原有 RMP 和变更历史维护完成后，Workflow 修复或补齐已发布索引，并按学期和格式保留两代。
原始历史快照永不删除；固定到更早版本的游标仍然正确，但可能需要完整重建。

索引包含压缩的规范化元数据、班次筛选字段、排序词表和 MiniSearch 索引。
键包含 run、学期和格式版本，解压限制为 192 MiB，恢复前校验 SHA-256。
损坏索引安全回退，并由预构建命令重建。分析器、规范化、索引输入或 MiniSearch
序列化发生变化时，需要提升 `SEARCH_ARTIFACT_VERSION`，并在读取端发布前重新预构建。

新服务进程仍要下载并解压索引，且从数据库补全可见班次。本改动从常见首次请求中移除了
全量原始数据传输、规范化和分词，但不保证立即返回，也不会预热每个 Serverless 实例。
现有精确课号实时路径及官方服务延迟不变。部署前应在隔离的代表性数据库测量冷、热端到端延迟。

## 共享响应缓存

公开索引搜索响应使用 30 秒浏览器缓存、五分钟共享缓存和十分钟 stale-while-revalidate 窗口。不同筛选 URL 与固定版本游标各自使用独立缓存键。失败请求不缓存。浏览器遵循缓存头，开启调试缓存绕过时除外。`Server-Timing` 提供源站搜索耗时，便于区分数据库与索引处理时间、网络延迟。

课程发布成功后会执行搜索索引维护，即使独立的 RMP 或课程变更历史维护失败。变更历史查询超时后回滚到保存点，缩小课程批次重试。外层事务仍以完整学期为单位原子发布，并遵循运行时间预算。

## 统一搜索与精确字段筛选

全站搜索输入使用同一个 `SearchField`，由调用处配置用途、图标、标签和布局。课程页与学业规划共同调用 `searchCatalogWithRelated`，规划不再走独立的精确查询与最多四条建议的小数点兜底逻辑。

可输入 `prereq:"MATH 1151.01"`、`title:"Software"`、`instructor:"Jane Smith"`、`subject:CSE` 或 `number:2221`。多个字段与普通关键词按“同时满足”组合，保留小数点课号，按完整词边界匹配，并在分页前筛选。教师条件与其他班次条件必须匹配同一个班次。`prereq:` 只查官方先修要求文字，不判断个人是否符合选课资格；普通关键词评分仍排除先修要求末尾，避免把“要求先学某课程”误当作该课程本身。

精确字段使用已发布的目录索引。索引不可用时明确报错，不会偷偷改成语义不同的官方关键词搜索；语法错误在读取数据库前返回。查询上限为 200 字符、十二个字段条件。

基础课号搜索能返回实际的 `.01`、`.02` 等课程。规划中打开不存在的基础课号时，会展示当前校区、学期实际发布的小数点版本供用户明确选择，不会自动替换成其中一门。要求或推荐上下文的搜索顶部提供“全部课程搜索”面包屑，可返回整体搜索。

### 已核验的小数课号示例

2026 年 11 月 26 日，官方对 `ECON 2001` 的基础课号精确查询没有独立课程，而已发布目录包含 `ECON2001.01` 和 `ECON2001.03H`。官方普通关键词查询还会返回描述中提及该数字的其他课程。因此，课号系列恢复会按专业及课号边界精确筛选，读取有上限的完整分页，再让用户明确选择真实变体，不会直接选中第一个关键词结果。
